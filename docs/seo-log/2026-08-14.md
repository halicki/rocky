## Correction: the queued canonical sweep is unnecessary

The 08-10 run added **Amendment 6** (Rule 6 mechanical-sweep exemption) and queued a sweep of all 40 canonicals, on the diagnosis that `next.config.ts` sets `trailingSlash: true` while every canonical in the repo declares the slash-less form, sending Google a contradictory signal.

**The source half of that is true; the conclusion is not.** Verified in production today:

| URL | source declares | **served HTML** |
|---|---|---|
| `/blog/canggu-surf-forecast/` | no slash | `…/blog/canggu-surf-forecast/` |
| `/blog/best-time-to-surf-canggu/` | no slash | `…/blog/best-time-to-surf-canggu/` |
| `/surf-lessons-canggu/` | no slash | `…/surf-lessons-canggu/` |
| `/batu-bolong-surf/` | no slash | `…/batu-bolong-surf/` |

Next.js **normalises the canonical to the trailing-slash form at render time** when `trailingSlash: true` is set. Every page already serves a canonical that agrees with the 308 redirect and with the sitemap. There is no contradictory signal, and a sweep of the source strings would be a **no-op on output**.

**The sweep is cancelled.** Amendment 6 (the mechanical-sweep exemption itself) stays — the mechanism is sound and will be useful — but its motivating case was misdiagnosed, because the 08-10 run read the source and never checked the served HTML. The `surf-coaching-video-analysis-canggu` duplicate is real but has some other cause; the likely candidates are historical indexation predating `trailingSlash`, or external links to the slash-less form. It is 5 impressions and does not justify further work now.

Recorded as a standing lesson: **verify a defect in the served output before writing a rule to fix it.**
