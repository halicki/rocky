## The diagnostic yesterday's log asked for: why `/blog/kids-surf-lessons-canggu/` is invisible

Note 3 of the 09-03 log registered this: *"The loop's best-performing blog page cannot be
selected, protected or replicated by any current rule. This deserves its own diagnostic
before it deserves an action."* Run today, read-only, three extra filtered GSC calls.

**The page, this window**: 35 impressions, **5 clicks, 14.3% CTR**, position 9.6 — the best
converting page on the site by a factor of ~1.5 over the homepage and ~20× over the large
forecast pages.

**The finding, stated plainly:**

| Query rows for this page | 28-day window | **90-day window (06-04 → 09-01)** |
|---|---|---|
| Rows GSC will name | **0** | **0** |
| Page totals over the same span | 35 impr / 5 cl | **110 impr / 7 cl / pos 8.6** |

**Zero named queries across ninety days and 110 impressions.** This is not a gap in the
loop's instrument and not a defect in the join — it is GSC's own anonymisation threshold.
Queries issued by too few distinct users are withheld by policy, and this page's entire
demand sits below that threshold.

The daily series shows why, and it is the useful half of the finding:

| Day | Impr | Clicks | Position |
|---|---|---|---|
| 08-15 | 5 | **1** | 6.6 |
| 08-24 | **1** | **1** | **1.0** |
| 08-27 | 4 | **2** | 7.0 |
| 08-31 | 2 | **1** | 8.0 |

Four of the twenty-eight days carry all five clicks. On 08-24 the page took **one click on
one impression at position 1.0**. That is the signature of a hyper-specific long-tail query
— a parent typing a full sentence — matched almost exactly by a page written to answer it.

**The mechanism is therefore self-limiting in a way no rule anticipated: the same property
that makes this page convert at 14.3% is what makes it unnameable.** It ranks 1st–8th for
questions so rare that GSC will not report them, and rarity is precisely the anonymisation
criterion. A page cannot simultaneously be high-CTR-long-tail and query-visible.

**Consequences for the playbook, registered but NOT written into it** (the evidence closed
today; v3's discipline forbids amending on the same run that produces the reading):

1. **Every rule the loop owns selects targets by named query.** Rule 1's visibility gate,
   Rule 2's ownership audit, Rule 3's demand test and Rule 4's snippet logic all require a
   query to act on. The site's best-converting page is invisible to all four **by
   construction**, and so is every future page like it.
2. **A page-level CTR selector would see it.** The one metric that identifies this page —
   clicks ÷ impressions at page granularity — is already in every snapshot and is used by
   no rule as an *entry* condition. Rule 4 uses it only as an exclusion (`CTR ≥ 2% → skip`).
3. **This inverts Rule 4's exclusion for a whole class of page.** Rule 4 skips high-CTR
   pages because they need no snippet help. Correct — but it means the loop has no rule that
   ever *looks at* a page that is working, and therefore no mechanism for asking what made it
   work. Three of today's sixteen converting pages are in this class
   (kids 14.3%, video-analysis 33%, over-40 4.3%) and all three are small.

This is a proposal to the owner, not a self-authorisation. The loop is not writing itself a
Rule 8.

**The defect, named for the record.** v4's escalation was built to break a deadlock between a
hard content obligation and a hard ownership gate. It broke the deadlock — the loop no longer
stalls — but it replaced a stall with an **unbounded wait**. There is no timeout, no fallback
and no re-escalation, so a ticket that is never answered silently *deletes* the content
obligation. An escalation that removes the duty it was protecting is inverted, not merely
slow. The loop cannot repair this itself: writing a fourth option is exactly what v4 forbids.
